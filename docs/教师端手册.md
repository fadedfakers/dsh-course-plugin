# 至圣先师鼹鼠精 · 教师端

> 课程答疑与作业批改面板 —— **教师端**使用手册（学生端是「鼹鼠仔」）
> 相关文档：[设计原则](../课程中心/设计原则.md)｜[课程数据模型](../课程中心/课程数据模型.md)｜[验证清单](./HANDOFF-验证清单.md)

---

## 一、这个东西解决什么问题

一门 30 课时的课，老师会面对三种噪声：

| 噪声 | 现状 | 鼹鼠仔怎么处理 |
| --- | --- | --- |
| **学生的问题散在群里** | 同一个知识点被问 8 遍，答完就沉底，下一届再问一遍 | 学生端把问题落成结构化条目（标题 / 知识领域 / 涉及概念 / 出处页），教师端按这两维聚合 |
| **作业批改要逐份看** | 一次批改判出十几条，几十个学生就是几百条 | AI 按**教案**初筛，**学生自己决定**哪些值得问老师；教师端默认只看学生公开过的 |
| **共性问题说不清** | 凭印象讲，讲完不知道补对没有 | 「共性问题」按课时把同一问题聚成一组，带出现次数；「课堂汇总」按课时给出问题分布 |

**核心设计取舍：决定权在学生手上。** 批改生成的问题默认**不公开**，学生逐条（或批量）
选择哪些交给老师。理由是：一次批改十几条，全量推给老师等于让他一天面对几百条，
最后他只能不看。让他只看学生主动送上来的那几条，每一条都是真的卡住了。

## 二、安装与启动

### 2.1 装什么

三个包（**学生端与教师端是两个可独立安装的插件**，共享一个公共数据面）：

| 包 | 作用 | 谁必须装 |
| --- | --- | --- |
| `dsh-course-core` | 共享内核：课程结构、教案、条目读写、模型调用、缓存 | 两端都要 |
| `dsh-course-student` | 学生端面板（路由前缀 `/cip-stu`） | 学生装；老师对测时也装 |
| `dsh-course-teacher` | 教师端面板（路由前缀 `/cip-tea`） | 老师装 |

> **路由前缀为什么必须不同**：DSH 的 `webServer.register` 对重复的 `(kind, path)`
> 会**直接抛错** —— 路由模式属于组合级契约。所以两个插件各带自己的前缀，
> 也正因为前缀不同，它们**能装在同一个 DSH 进程里同时运行**，这是一台机器上对测两端的前提。

安装（开发机）：

```powershell
cd 课程发布
powershell -ExecutionPolicy Bypass -File .\teacher.ps1 -Install -WithStudent
```

`-Install` 会把三个包按 Junction 链进 DSH profile，`-WithStudent` 连学生端一起装。
去掉 `-WithStudent` 就只装教师端。

### 2.2 启动

```powershell
cd 课程发布
# 最简：用内置默认工作区
powershell -ExecutionPolicy Bypass -File .\teacher.ps1

# 指定课程码与工作区
powershell -ExecutionPolicy Bypass -File .\teacher.ps1 -CourseCode "DL2026-SPRING" -Workspace "D:\courses\dl2026"

# 只看会设什么，不真启动
powershell -ExecutionPolicy Bypass -File .\teacher.ps1 -DryRun
```

**为什么要专用脚本**：宿主靠环境变量 `CIP_ROLE` 判断身份，而它**缺省是 `student`**
（刻意 fail-closed —— 学生开箱即得教师权限，比老师多设一个变量糟得多）。
所以老师每次启动都必须显式声明身份。环境变量只对**本次启动的进程**有效，
不写注册表、关窗即失效 —— 教师身份不该粘在机器上。

### 2.3 环境变量（脚本已代劳，排错时用得上）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `CIP_ROLE` | `student` | **必须设为 `teacher`** 才是教师端 |
| `CIP_WORKSPACE` | 内置路径 | 课程工作区根目录 |
| `CIP_TEACHER` | 系统用户名 | 答复与审计里署的名 |
| `CIP_COURSE_CODE` | 空 | 课程码，随 `info` 下发给学生端显示 |
| `CIP_STU_PREFIX` / `CIP_TEA_PREFIX` | `/cip-stu` / `/cip-tea` | 路由前缀（两个必须不同） |
| `CIP_MAX_SUB_BYTES` | 4 MB | 单份提交的文本上限 |
| `CIP_MAX_BLOB_BYTES` | 12 MB | 单个附件上限 |
| `CIP_KATEX_DIR` | 包内自带 | KaTeX 目录（公式渲染） |

## 三、界面导览

侧栏底部会有两个入口：**「鼹鼠仔（学生）」**与**「鼹鼠仔（教师）」**。
老师对测时两个都装，学生只装前者。

教师端七个标签页：**学生 / 提问与审计 / 共性问题 / 学生提交 / 课堂汇总 / 教案补全 / 归档发布**。

### 3.0 学生 ← 「谁提问的」原来写的是 Administrator

打开教师端，提问者那一栏原来是 **Administrator**。那不是学生，是这台
Windows 机器的用户名（身份 = `CIP_STUDENT` 环境变量 ‖ `USERNAME`）。
对「谁提问的，好针对性教学」这个问题，那个答案一点用都没有。

现在是这样：

| 名字从哪来 | 写在哪 | 谁说了算 |
| --- | --- | --- |
| **老师名册** | `<课程目录>/学生名册.json` | ✅ **最高** |
| 学生自报 | `课程问题池/学生/<学号>/学生信息.json` | 次之 |
| 学号 | —— | 兜底 |

- **学生端**：第一次打开面板会请他填一次「学号 / 姓名 / 班级」
  （写在本机 `我的身份.json`，已在 `.gitignore` 里，不进任何仓库）。
  不填也能用，只是老师那边看到的还是一串机器用户名 —— 界面会把这句话说清楚。
- **教师端「学生」页**：左边是全班名册，每行带可比较的计数
  （提问 / 已公开 / 未批改 / 阻塞级 / tokens），点「补姓名」就把学号改成真名。
  右边是选中那个人的全部情况，并**直接给出结论**：

  > **这个人需要你做什么**
  > · 2 份提交还没批改
  > · 1 条阻塞级问题
  > · 1 条已公开但你还没答复

  以及「卡在哪几课」（按课时聚合，带最重严重度与知识领域）。

**改学号会搬迁，不会丢**：学号就是目录名（`课程问题池/学生/<学号>/`），
改学号时插件先把「会搬多少条提问、多少份提交」报出来，**确认后**才搬；
目标目录已存在时**不合并**（合并两个学生的数据必须由人决定）。
理由：不搬的后果是「历史提问与作业留在旧目录里，从此谁也看不见」——
数据没丢，但等于丢了，而且不报错。

### 3.0b 换课（同时教几门课时）

顶栏显示「你在看哪门课」。有**多于一门**课（`<根>/课程/<课程码>/`）时
它就是一个下拉框：

```
课程  [ DL2026　深度学习 ▾ ]
```

切换是**热切换，不用重启**。换的只有**私有数据**那一半
（提问 / 作业 / 教案草稿 / 名册）；课件、教案、结构索引是全校共享内容，
住在工作区根目录，不受影响。换完所有列表自动重拉。

> ⚠️ 指定一个不存在的课程码会**明确报错**，不会悄悄回落到当前课程。
> 「切到 B 课，结果你还在看 A 课的数据」是这类功能最坏的失败方式：
> 界面一切正常，而你在给 B 班讲 A 班的问题。

> **学生不需要输课程码。** 课程码随公开仓一起抵达（仓里带 `课程配置.json`），
> 插件自己认。课程码是给**老师**在一台机器上分多门课用的：
> `<根>/课程/<课程码>/` 是每门课的私有数据目录，公开仓也按课程码命名。

### 3.1 提问与审计

默认**只显示学生公开过的条目**，并如实告诉你「另有 N 条学生未公开」。

右上角有一个开关 **「只看已公开 / 全部条目（含未公开）」**：

- **只看已公开**（默认）：学生主动送上来的，是他真的卡住的地方
- **全部条目**：审计视图。用于排查「某个学生是不是卡住了」——
  他可能攒了一堆问题没敢问，这在这条视图里一眼能看出来

每条可以做三件事：

| 动作 | 效果 |
| --- | --- |
| **答复** | 追加进该条目的对话线程，学生端立刻看到，标为「教师已答复」而非「AI 答复」（两者可信度不同，界面不混为一谈） |
| **审计 → 值得共享** | 在 `课程问题池/公共/` 写一份**策展副本**，下次发布带给全班。原条仍留在该学生的私有目录，他的历史不会消失 |
| **审计 → 仅本人** | 只答复，不进公共池 |

> 答复与审计是**两个动作**，这是刻意的：经常有「只答本人」或「先答再决定」的情况。
> 混在一个动作里会出现「为了答复学生而不得不先决定是否公开」这种别扭流程。

### 3.2 共性问题

按课时 + 问题性质把重复出现的问题聚成一组，带出现次数与样例。
用途：决定**下一轮录课要补讲什么**。

### 3.3 学生提交

所有学生的作业提交（按学生分目录），可筛选、可下载、可查看批改结论。
`_附件/` 与 `*.versions.json` 这类记账文件已从列表里排除 ——
它们不是「学生交的作业」。

### 3.4 课堂汇总

按课时给出问题分布，用于讲评时对照。

### 3.5 教案补全 ← 减少工作量最多的一页

一句话：**你准备 PPT，教案由模型补，你只做审批。**

老师的原话是「一般会准备 PPT，但不一定会写教案」。而批改、答疑、验收
全都以教案为对齐基准 —— 教案缺一节，那一节的批改就只能退化成「通用工程
规范初筛」。所以这一页把「写教案」变成「审教案」。

页面分三段：

**① 大纲体检** —— 30 个课时各自缺什么，一次说清。

| 指标 | 含义 |
| --- | --- |
| 有教案 / 缺教案 | 磁盘 + 索引双重确认；还会标出「有教案但缺验收标准」这种**看起来有、实际不能用**的情况 |
| 有课件页 / 无课件页 | 从课件的课时分隔页推断出页码范围；标「推断」还是「已确认」 |
| 可自动补 | 有课件文本**或**示例代码 → 材料够，能让模型补 |
| 材料不足 | 两样都没有 → 先生成只会得到常识拼凑的教案，所以**不提供**生成按钮 |

「缺教案」和「缺课件」是**两种补救**（前者能自动补，后者要去录课），
所以分开报，不合成一个「完成度」数字。

**② 逐课时待办** —— 每个课时一行：标题、教案状态、课件页码、
`确认页码` / `生成教案` 按钮。缺教案且材料够的排在前面。

> **页码为什么要你点一下「确认」**：PPT 里的课时标题与索引标题**并不严格
> 一致**（PPT 写「用线性代数勒死自己」，索引写「从统计学习理论到深度学习的
> 矩阵化重构」），而且实测 30 个课时只有 **10 张分隔页** —— 一个分隔页常常
> 覆盖两个课时。由代码猜出来的页码一旦进了教案，就会变成批改的基准。
> 错的基准比没有基准更糟。所以：**自动推断可用，但要点一下才算数**；
> 确认过的写进 `教案草稿/_锚点.json`，之后一直用它。

**页码是「看着 PPT 圈的」，不是盲填数字。** 点某个课时的「改页码 / 设置页码」，
展开的编辑器里除了两个输入框，还有一个**课件窗口**：

```
看课件（学生端的课件页就长这样）          第一章 第二章 第三章
[1][2][3][4][5][6][7][8]…                        ← 页条
← 上一页   第一章 第 4 / 58 页   下一页 →   这一页作起始   这一页作结束
┌────────────────────────────────┐
│  （课件页本身：文字与图片按学生端同一套布局渲染）    │
└────────────────────────────────┘
这一页的文字…
当前圈定：第 10 – 58 页
```

- 页条里**落在圈定范围内的页码高亮**，一眼看出「我圈的这一段对不对」
- 翻到第一页点「作起始」、翻到最后一页点「作结束」，不用手输数字
- 渲染用的是**学生端课件模块同一套类**（`k17` 缩放层 / `k47` 形状 / `k55` 图片占位），
  所以「学生看到的」和「你看到的」是同一套布局规则，不是照着画的
- 图片加载不出来时给明确占位（不是空白）

**③ 草稿审批** —— 生成出来的东西叫**草稿**，落在 `教案草稿/`，
**不会**自动进 `详细教案/`。

```
生成（模型读课件 + 示例代码 + 同风格教案样例）
   ↓  写进 教案草稿/课时N_<标题>.md
读一遍 → 可以在面板里直接改 → 保存修改
   ↓  点「采纳」
写进 <模块>/详细教案/课时N_<标题>.md，并同步 课程结构索引.json
```

- **采纳**是唯一会写正式教案的入口。教案是批改逐条对标的基准，
  一份没人看过的自动文本一旦成了基准，错误会被放大到每个学生身上。
- 同名教案已存在时会**先备份**到 `教案草稿/_历史/`，再覆盖（不会静默冲掉旧版）。
- 「不采纳」只是标记，草稿留着 —— 过两天想捡回来还在。
- 每份草稿都会显示**生成时看到了什么**（课件几页 / 代码几份 / 风格样例是哪一课 /
  缺什么材料）。生成质量出问题时，第一件要查的就是「它到底看到了什么」，
  而不是重跑一次。

**模型与费用**：这一页是教师端**唯一**会调用模型的地方，用你**自己的**额度。
页面顶部有一个模型下拉框，可选「跟随会话默认」或指定某个模型，选择记在
`教案草稿/_模型.json`（不写进 DSH 设置，也不和学生端共用）。
其余所有动作（审计、汇总、发布）都是纯读写，**一分钱不花**。

**骨架是可替换的**：默认骨架（目标 / 推导 / 实操 / 验收标准 / 当堂交付物）
是从这门课**已有的 18 份教案**里提取的。要换，就在课程目录根部放一份
`教案模板.md`，里面用 `{{课时}}` 与 `{{标题}}` 作占位符即可。

### 3.6 归档发布

把公共面的内容发布成一个**公开仓**，学生 clone 后即可拿到：
课程结构、已发布教案、公开问答、课件图片（webp）。

```powershell
node 课程发布\course-repo.mjs status    # 看有哪些待发布
node 课程发布\course-repo.mjs publish   # 生成到 课程发布\public\
```

发布前会做**泄漏检查**：确认私有提问、学生作业、未发布的教案没有被带出去。

## 四、工作区结构

老师机上的私有一份、学生 clone 公开那份，目录分工是**每个位置只有一个写入方**，
所以不会互相覆盖：

```
<工作区>/
  课程中心/
    课程结构索引.json        课程骨架（模块 / 课时 / 教案文件名）
    课程配置.json            课程名 / 课程码 / 目标（换课程只改这里）
    预览数据/                课件 JSON 与 media/ 图片
    .cache/                  派生数据缓存（自动生成，可随时删）
    _插件源码/panel.css      面板样式表（老师机直接读这份，改完刷新即生效）
  教案/                      各模块教案
  课程问题池/
    公共/                    老师写（策展后），学生读
    学生/<学号>/              该学生自己写，老师读
  作业提交/<学号>/            该学生自己写，老师读
```

**只有一个写入方**这条规则的重要性：它让「老师机和学生机各有一份工作区、
通过 git 同步」这件事不会产生冲突 —— 学生推不上公共面，老师也不会覆盖学生目录。

## 五、缓存

面板会缓存**派生数据**（课程树、教案存在性、提交清单），因为：

- `hasPlan` 要对 30 个课时逐个查文件
- 提交清单要扫目录、每个版本再列一次附件目录

每次刷新面板都付这个成本不划算，而原始数据一分钟内不会变。

两条硬规则：

1. **单一事实来源永远是磁盘上的原始文件。** 缓存条目都带「来源文件 + mtime + size」，
   原始文件一变就整体失效。最坏情况是「多算一次」，绝不会出现「缓存说教案在、实际不在」。
2. **磁盘快照坏了就当没有。** 快照在手改坏、版本不符、工作区换掉时**静默退回重算**。
   缓存把面板弄崩是最不可接受的失败方式。

```powershell
# 清缓存（加完教案、改完索引想立刻生效时）
#   删掉目录即可，不影响任何原始数据
Remove-Item -Recurse -Force 课程中心\.cache
```

`课程中心/.cache/` 在 `.gitignore` 里，不会被提交。

> **不缓存模型调用的结果。** AI 答复是学生的钱换来的，
> 一旦缓存错位就会给出「看起来对、其实答的是别的问题」的内容。不值得。

## 六、排错

### 6.1 面板显示「未知动作：xxx」

**宿主半区没重启。** 路由与 API 动作是宿主注册的，改完宿主代码必须重启 DSH；
只刷新浏览器不够。

```powershell
# 一眼看出「动作在不在」
start http://127.0.0.1:3080/cip-tea-diag/
```

诊断页会逐个测本端与**对端**的 API 与静态资源，比翻日志快。

### 6.2 启动报 `EADDRINUSE`

旧进程还占着端口。DSH 会 spawn 子进程，父进程被杀后子进程可能继承监听 socket。

```powershell
netstat -ano | findstr :3080 | findstr LISTENING   # 找到 PID
Get-Process -Id <PID> | Select-Object StartTime    # 比它和你改文件的时间
Stop-Process -Id <PID> -Force
```

`scripts/start_deepseek_harness.ps1` 已做整棵进程树停止 + 端口可达探测 + 退出码诊断；
若你用的是它，正常情况下不会走到这一步。

### 6.3 教案显示「未撰写」，但文件明明在

先清缓存（`Remove-Item -Recurse -Force 课程中心\.cache`）；还不对就检查
`课程结构索引.json` 里该课时的 `plan` 字段是不是文件名（它存的是**文件名**，不是路径）。

索引是手工维护的派生文件，漏改不报错 —— 直接去「教案补全」页点
**「重建索引」**：它会扫一遍 `详细教案/`，把每一处改动列出来给你看。
（顺手也会报出「文件名不含 `课时N_` 前缀、对不上任何课时」的文件，
以及同一课时有多份教案的冲突。）

### 6.4 课件图片加载不出来

检查 `课程中心/预览数据/media/<章>/` 下有没有对应的图。
公开仓分发的是 `.webp-out/` 那份（体积约为 PNG 的 30%）；
MP4 是有意不随课程包分发的（PPT 内嵌录屏片段，45 MB）。

## 七、一条命令跑全部校验

改完任何东西，**重启之前**先跑这个：

```powershell
cd <工作区>
node 课程发布\tools\build-clients.mjs
```

五步都必须显示「通过 N 项，失败 0 项」：

| 步骤 | 做什么 |
| --- | --- |
| 1/5 校验多课程路由 | 旧布局 / 共享式布局 / 课程码 / 自动挑课，四种形状都要解析得对 |
| 2/5 校验教案补全 | 骨架解析、课时锚点、草稿区、采纳（含覆盖备份）、索引重建、真实工作区体检 |
| 3/5 抽取共享渲染核心 | 从源客户端抽出两端共用的渲染内核（markdown / 公式 / 徽标） |
| 4/5 校验客户端 bundle | 用假 React / 假 ModuleLoader **真的物化执行**三个 bundle，并驱动渲染（含教师端「教案补全」与「学生」整页展开、学生端「我是谁」卡片） |
| 5/5 校验宿主与双插件挂载 | 在隔离的临时工作区里跑完整流程：提问 → 答疑 → 批改 → 审计 → 教案生成 → 采纳 → 名册 → 改学号搬迁 → 换课 → 发布 |

第 2 步会**写课程结构索引**（那是共享内容），所以它在自己的临时工作区里跑，

第 5 步**必须**用隔离工作区：它会真的审计为「值得共享」，那会在公共面写下副本 ——
公共面是给全班看的地方（踩过一次，跑完发现公共面里躺着测试提问）。

## 八、设计边界（哪些事这个插件不做）

- **不代替老师判断。** AI 按教案初筛，结论逐条带证据；「无法核验」是一个正常结论，
  不是一个要绕过的错误。
- **不改学生的东西。** 教师端的审计只写策展副本，原条留在学生目录里。
- **不动 DSH 的设置。** 模型选择存在课程工作区里（学生端 `学生/<学号>/模型选择.json`、
  教师端 `教案草稿/_模型.json`），不碰 `agentDefaultModel` ——
  那是整场会话级别，属于别的插件的领地。
- **不缓存模型结果。** 见第五节。
- **不猜课时映射。** 课件里的课时分隔页用几何签名切分，但「课件第 3 段对应索引第几课时」
  由人确认后写进锚点文件，不自动猜 —— 猜错会让批改对错教案。
- **自动生成的教案不会自动生效。** 草稿必须由老师点「采纳」才进 `详细教案/`。
  这是刻意的：教案是批改的基准，基准不能由代码自己背书。

### 3.5b 草稿能一轮一轮改（对话式）

生成只是起点。老师看出来的问题几乎都是**局部的**——「这节推导跳步了」
「验收标准太虚，改成可判定的」「第 12 页那张图要讲进去」。所以草稿面板有第三个
页签 **「继续改（对话）」**：

```
[圈一块图] [用选中的文字]        已圈 1 / 4 块
┌────────────────────────────────┐
│   （课件页：可以拖选文字，或拖一个框圈图）  │
└────────────────────────────────┘
这一轮要改什么？例如：把「推导」第二节的矩阵求导补上逐步说明
[让模型改这一轮]

已经改了 2 轮
┌ 第 1 轮 │ 改了 推导 │ 8000 → 8042 字 │ 带证据 1 块 │ 截图 1 张
│ 把推导第二节补上逐步说明                              [退回这一轮之前]
└──────────────────────────────────────────────
```

- **取证方式和学生提问是同一套**：拖选文字走浏览器原生 selection，
  框选走共享内核里那个 `cropToPng`（学生框选截图用的就是它）。
  圈到的内容**截图 + 文字都带上**——这门课大量用截图代替公式，只发坐标等于没给。
- **只改要求的地方**：system 里明确要求「其余部分逐字保持不变」。
  模型偶尔还是会把某一节写丢或写空，这时**自动回退到原内容**并标出来
  （`⚠ 新稿把 验收标准 写空了，已保留原来的内容`）——
  一份丢了一节的教案比原来更糟，而老师要逐字比对才能发现。
- **每轮都留快照**，每轮都能「退回这一轮之前」。逐轮改就必须能回退。
- 这一页同样**花老师自己的额度**（一轮一次调用）。

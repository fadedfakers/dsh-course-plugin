# 教师机冷启动清单

> 面向：**换一台电脑**从零把教师端跑起来的人。
> 每一步都带**可执行的验收判据**——不是"应该能行"，是"跑这条命令，看这个结果"。
> 任何一步判据没过就不要往下走：后面每一步都建立在前一步之上，跳过只会让报错长在别处。

---

## 先弄清：这个仓能给你什么、不能给你什么

| | 在 `dsh-course-plugin`（本仓） | 在**课程仓**（如 `DSH-algorithm`） |
| --- | --- | --- |
| 插件本体（三个包） | ✅ | ✅（发布时会复制到 `panel/`） |
| 界面与逻辑 | ✅ | |
| **课程内容**（教案/课件/索引） | ❌ **不在本仓** | ✅ |
| `课程中心/` 工作区结构 | ❌ | ✅ |
| 学生用的 `install.ps1` | ⚠️ 只是一份**副本** | ✅ 这才是它的家 |
| `~/.dsh/cip-workspace.txt` | 本仓不管 | 由课程仓的 `install.ps1` 写 |

**最容易踩的误会**：以为装了插件就有课了。装完插件只是有了"面板"，
**面板要有工作区才能显示东西**——工作区是课程仓的事。所以教师机的顺序是：
**先装插件（第 1-2 步）→ 再把工作区指过去（第 3-5 步）**。

> 本仓 `templates/` 下的 `install.ps1` 是为**课程仓**准备的（它要 `<仓根>/panel/`），
> 在本仓里跑会在"检查本仓文件"那一步直接失败。别在这里跑它。

---

## 第 1 步：装 DSH

```powershell
npm i -g @deepseek-ai/dsh
```

**判据**

```powershell
dsh --version          # 必须打印出版本号，不能是 CommandNotFoundException
```

> 本机踩过的坑：`dsh` 不一定在 PATH 里（当时只有 `@deepseek-ai/dsh` 这个包，
> 没有 binshim）。若报找不到命令，用可执行入口直接跑：
> `node "$(npm root -g)\@deepseek-ai\dsh\lib\bin.js" --version`

---

## 第 2 步：装插件本体（**两个包**，不是三个）

学生机装「内核 + 学生端」，教师机装「内核 + 教师端」。**两个端互不引用**，
装另一个端是多余的。

```powershell
dsh plugin --profile web add github:fadedfakers/dsh-course-plugin#path:dsh-course-core
dsh plugin --profile web add github:fadedfakers/dsh-course-plugin#path:dsh-course-teacher
```

**为什么内核必须一起装**（实测过，不是理论）：每个端通过
`src/core-loader.js` 按**绝对路径**去 import 内核：

```
CORE_DIR = <profile>/node_modules/dsh-course-core
```

只装一个端时 `dsh plugin add` **会成功退出（exit=0）、包名也会进 bundles，
但面板起不来**，报错是 `ERR_MODULE_NOT_FOUND ...dsh-course-core\src\index.js`。
——这正是那种最难查的"装了但什么都不出现"。

**判据**（三步都要看）

```powershell
# ① 两个包都要在 dependencies 里
node -e "const p=require(process.env.USERPROFILE+'/.dsh/profiles/web/package.json');console.log(Object.keys(p.dependencies))"

# ② 两个包名都要在 dsh.profile.bundles 里（漏一个 = 装了但不挂载）
node -e "const p=require(process.env.USERPROFILE+'/.dsh/profiles/web/package.json');console.log(p.dsh.profile.bundles)"

# ③ 内核真的能被装进来的端加载
node -e "import(process.env.USERPROFILE.replace(/\\\\/g,'/')+'/.dsh/profiles/web/node_modules/dsh-course-teacher/src/core-loader.js').then(m=>m.loadCore()).then(c=>console.log('内核导出',Object.keys(c).length,'项, createCore=',typeof c.createCore))"
```

预期：① 有 `dsh-course-core` 与 `dsh-course-teacher`；
② 两个名字都在 bundles 数组里；③ 打印 `内核导出 167 项, createCore= function`。

> 想先干跑一遍不碰真实 profile（隔离环境，跑完即删，退出码 0 通过 / 1 产品问题 / 3 网络问题）：
>
> ```powershell
> powershell -ExecutionPolicy Bypass -File .\tools\probe-newuser-install.ps1
> ```

## 第 3 步：拿到课程工作区

工作区 = 那个含 `课程中心/` 的目录。两条来源，按你的身份选：

| 身份 | 从哪拿 |
| --- | --- |
| 教师 | clone 你的**私有**课程仓（内容 + 学生数据都在里面） |
| 学生 | clone 课程**公开**仓，然后在仓根跑它的 `install.ps1` |

**判据**（这不是形式检查——解析器就是照这个认的）

```powershell
Test-Path '<工作区目录>\课程中心\课程结构索引.json'    # 必须是 True
```

> 解析器判定"这是不是工作区"的依据**就是**这个文件。造错了的表现是面板空白，
> 而且**不报错**。所以先自己确认它存在，再去配路径。

---

## 第 4 步：把工作区路径告诉插件（**新机器上最容易漏的一步**）

不改任何代码，二选一：

```powershell
# 方式 A：环境变量（当前会话/永久都行）
$env:CIP_WORKSPACE = '<你的课程工作区目录>'

# 方式 B：写一行到固定文件（重启后依然有效，推荐）
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.dsh" | Out-Null
Set-Content -Path "$env:USERPROFILE\.dsh\cip-workspace.txt" -Value '<你的课程工作区目录>' -Encoding utf8
```

**共享式布局**（根目录放共享内容、每门课在 `课程/<课程码>/` 下）再加一行：

```powershell
$env:CIP_COURSE_CODE = '<课程码>'    # 不设则自动挑第一个
```

**为什么这一步不能省**：解析链的顺序是
`CIP_COURSE_DIR` → `CIP_WORKSPACE` → `~/.dsh/cip-workspace.txt` → **内置默认值**，
而那个内置默认值是**教师机的绝对路径**（写死在 `dsh-course-core/src/host.js` 的
`DEFAULT_WORKSPACE`）。在教师本机上它恰好存在，所以一切正常；**换台机器就必然落空**。

**判据**

```powershell
# 一条命令给结论：它解析到了哪、配对没有
node tools/probe-workspace.mjs
```

预期最后一行是 `✓ 工作区解析正常，课程数据可读。`

> ⚠️ **别用 `probe-fresh-machine-workspace.mjs` 当判据** —— 它的用途是"把每一环都指到
> 不存在的地方"，而**在教师本机上它永远测不出落空**（兜底那个目录真的存在，
> 会正常命中）。这个坑我踩过：脚本输出看着一切正常，其实是假阴性。
> 要验"落空时不再静默"，看 `verify-workspace-unresolved.mjs`（它用注入的兜底值
> 强制走那条分支，14 项断言）。

配好之后，`dsh` 启动时应当看到：
- 正常：`[至圣先师鼹鼠精·教师端] 就绪 v0.2.0 · … · 工作区=<你的目录>（环境变量 CIP_WORKSPACE …）`
- 没配好：`⚠ 没找到课程工作区：…` 后面跟着**三条修法**（这条提示就是本轮补的）

---

## 第 5 步：配置 GitHub Token（只教师端需要）

用于课程仓的建仓与推送。**放在文件里，不要写进任何配置文件**：

```powershell
Set-Content -Path "$env:USERPROFILE\.dsh\github-API.txt" -Value '<你的 token>' -Encoding utf8
```

启动脚本会读它并注入 `GITHUB_TOKEN`（已设则不覆盖）。**判据**：启动输出里有

```
GitHub token loaded from ... (GitHub MCP enabled)
```

没有这一行 = 少了 GitHub 工具，但**不影响面板**（这一项失败不该拦住启动）。
另：token 只在**教师机**上需要；学生机不需要，也不该有。

---

## 第 6 步：重启 DSH

**宿主半区是进程启动时加载的**，所以前 5 步做完必须重启：

```powershell
.\scripts\start_deepseek_harness.ps1
```

只改客户端/CSS 才不需要重启（Ctrl+F5 即可）。

## 第 7 步：验收（每一步都有判据）

### 7.1 插件挂上了吗

```powershell
# 在插件仓根目录跑
node tools/check-loaded-plugin.mjs
```

预期：两个端 `deps=true bundles=true 物化=true`，且 `导出 name = course-panel-teacher`。
（这个脚本读的是 `%USERPROFILE%\.dsh\profiles\web`；要查别的 profile 就传路径当参数。）

### 7.2 面板在服务吗（**打正在跑的宿主**，别只看文件）

```powershell
# 前缀是 <prefix>.css / <prefix>-diag；默认 /cip-tea 与 /cip-stu
Invoke-WebRequest http://127.0.0.1:3080/cip-tea.css -UseBasicParsing | Select StatusCode, RawContentLength
```

预期 `200`，长度约 48 KB。

### 7.3 课程数据读到了吗（**这是"工作区配对了"的铁证**）

```powershell
$r = Invoke-WebRequest http://127.0.0.1:3080/cip-tea-api/info -Method POST -Body '{}' -ContentType 'application/json' -UseBasicParsing
($r.Content | ConvertFrom-Json) | Select workspace, workspaceResolved, workspaceLooksValid
```

预期：`workspace` 是你第 4 步配的目录，`workspaceResolved` 与 `workspaceLooksValid` **都是 True**。

```powershell
# 课程树应当有你全部课时
$t = Invoke-WebRequest http://127.0.0.1:3080/cip-tea-api/tree -Method POST -Body '{}' -ContentType 'application/json' -UseBasicParsing
($t.Content | ConvertFrom-Json).tree.totalLessons
```

预期：等于你课程的课时数（本课为 30）。

### 7.4 教案能打开吗（端到端最强的一条）

```powershell
# 注意：lesson.open 是**学生端**的动作，必须用学生端前缀
$b = '{"lesson":1}'
$r = Invoke-WebRequest http://127.0.0.1:3080/cip-stu-api/lesson.open -Method POST -Body $b -ContentType 'application/json' -UseBasicParsing
($r.Content | ConvertFrom-Json) | Select title, planRel
```

预期：返回课时标题与教案相对路径，且 `plan` 字段里有正文。返回 `未知动作` = 宿主没重启。

## 三个已知的"看着像坏了，其实不是"

1. **`/cip-tea-api` 直接 GET 会 404** —— 真实路由是 `<prefix>-api/<动作名>`，
   而且**必须 POST**（带 JSON body）。GET 打根路径必然 404，不代表没挂载。
2. **`lesson.open` / `item.share` 在教师端前缀下报"未知动作"是正常的** ——
   这两个动作**只注册在学生端**。诊断页 (`/cip-tea-diag`) 目前把这两条按教师前缀列，
   会误导成"宿主没重启"；以 `/cip-stu-api/...` 为准。
3. **`chapters` 是内置默认值** —— `第一章/第二章/第三章`。若你的课按"模块一…五"组织，
   建议在 `课程配置.json` 里显式写一段 `"layout": {"chapters": ["模块一", ...]}`，
   否则按章节名匹配的功能（如课件归位）认不出来。`/cip-tea-api/info` 的
   `layoutReport` 会告诉你每一项当前用的是默认值还是你的配置。

## 排障速查

### 先说一个查过很多次的坑：git 连不上，多半是代理配到了死端口

症状长这样（`dsh plugin add`、`git push`、`git clone` 都可能是它）：

```
fatal: unable to access 'https://github.com/...': TLS connect error:
       error:0A000126:SSL routines::unexpected eof while reading
```

**别急着怪网络，先查这两条：**

```powershell
git config --get http.proxy                                  # 有没有配代理
Get-NetTCPConnection -LocalPort 7890 -State Listen           # 那个端口有人在听吗
```

如果配了代理、而端口**没有监听**（代理软件没开），git 就会一直卡在 TLS 握手。
**Node / 浏览器不走 git 的代理配置，所以它们同时是好的** —— 这个反差最容易让人误判成
"网络时好时坏"。

修法（任选）：

```powershell
# A. 不需要代理：把配置删掉
D:\Git\cmd\git.exe config --global --unset http.proxy
D:\Git\cmd\git.exe config --global --unset https.proxy

# B. 需要代理：把代理软件启动起来，让端口真的有监听

# C. 临时绕过（不改配置）
git -c http.proxy= -c https.proxy= push
```

### 其余症状

| 症状 | 多半是 | 怎么确认 |
| --- | --- | --- |
| 面板出现但一片空白 | 第 4 步没做，或第 3 步的目录不对 | 7.3 的 `workspaceResolved` / `workspaceLooksValid` |
| 面板根本不出现 | 端与内核没一起装 | 第 2 步的三个判据 |
| 启动日志有 `⚠ 没找到课程工作区` | 新机器 + 没配路径 | 按提示的①②③改，重启 |
| 接口报「未知动作」 | 宿主是旧进程 | 重启 DSH（不是刷新浏览器） |
| `git` 报 TLS / could not connect | 代理配到了死端口 | 见上面那节 |
| 建仓/推送不可用 | 第 5 步没做 | 启动输出里有没有 `GitHub token loaded` |

## 最小可复现的机器清单

- Windows + PowerShell 5.1 可用
- Node.js ≥ 20
- git（**可以不在 PATH 里**，但 pnpm 解析 GitHub 依赖时要能找得到；装 Git for Windows 最省事）
- pnpm（`dsh plugin` 是它的薄封装）
- 到 `github.com` 与 `registry.npmjs.org` 的网络

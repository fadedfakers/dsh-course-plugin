# 课程发布协议（教师端操作手册）

> 这份文件回答一个问题：**我的团队和学生怎么协作，以及"发布"这件事到底怎么控制。**

---

## 一、核心设计：为什么必须是「两个仓库」

你的原话是"用 harness 接入一个共享的项目仓库，学生端无法看到所有内容，教师端有全局编辑权，并能选择发布的内容"。

这个目标有一个**结构性陷阱**必须先避开：

> ⚠️ **只读权限 ≠ 看不到未发布的内容。**
> 如果草稿和已发布内容在同一个仓库里，学生 `clone` 下来就能读到草稿。GitHub 的"只读"管的是**能不能改**，不是**能不能看**。

所以"选择发布内容"不能做成**过滤**（从全集里滤掉一部分），必须做成**复制**（只有被选中的才进入学生那一侧）：

```
┌─────────────────────────────────────────────────────────────┐
│  私有仓（只有你 / 信任的助教）                                 │
│  = 当前这个工作区 C:\...\暑期课程                              │
│                                                             │
│  · 全部 5 模块 30 课时（含草稿、未定稿教案）                     │
│  · 作业提交/ 批改结果/ 计分                                     │
│  · 问题池原始条目（含学生原话）                                 │
│  · 补充材料、提示词、README 等教师自用文件                       │
└──────────────────────────┬──────────────────────────────────┘
                           │  显式勾选 + 复制
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  公开仓（学生可见，只读）                                      │
│  = 课程发布/public/                                            │
│                                                             │
│  · 只有你勾选过的教案 / 代码示例 / FAQ                          │
│  · 课程.json（已发布内容的清单）                                │
│  · 学生在这里提 issue                                          │
└─────────────────────────────────────────────────────────────┘
```

**没被勾选的课时，在公开仓里根本不存在。** 这就是"学生端无法看到所有内容"的实现方式。

## 三、日常操作（三条命令）

在 `课程发布/` 目录下：

```bash
# 1. 先看会发出什么 —— 每次改白名单后都要先跑这个
node course-repo.mjs check

# 2. 确认无误再发布
node course-repo.mjs publish

# 3. 对比白名单与实际内容，检查差异
node course-repo.mjs status
```

`check` 会同时列出**刻意跳过的文件**（README、补充材料等非课时文档），让你确认它们确实不该公开。

### 怎么发布新课时

编辑 `publish.manifest.json`：

```json
"模块三": { "publish": true, "publishCode": true }
```

- `publish: true` → 该模块下所有 `课时N_*.md` 都发布
- 只想发几课：`"lessons": [13, 14]`
- **`README.md`、`关于连续的补充材料.md`、`绝妙的提示词.md` 永远不会被自动发布** —— 它们不符合 `课时N_*.md` 命名。这不是 bug，是防止误发。

### 发布节奏建议

**不要攒到期末一次发。** 建议：

- 每讲完一个课时，就把该课时教案勾上发布
- 发布信息写进 commit message：`publish: 模块三 课时13-15 教案`
- 学生看到的 `课程.json` 里有 `publishedLessons`，进度是透明的

## 四、学生提问怎么回流到你这里

### 通道（唯一一个）

**GitHub Issues**，模板在 `public/.github/ISSUE_TEMPLATE/课程提问.md`，共 9 个字段，其中三个是刻意设计的：

| 字段 | 为什么这么设计 |
| --- | --- |
| 第 3 项「你的原始理解」 | 学生用哪个词，说明他脑子里是哪个模型。转述成标准说法就丢失了这个信息 |
| 第 4 项「你已经试过什么」 | 过滤掉"伸手党"，也让老师知道该补哪一步 |
| 第 8 项「严重度」 | 有截止时间的阻塞问题优先处理 |

### 回流流程

```
学生提 issue
   ↓
node fetch-issues.mjs          ← 自动拉取到 inbox/
   ↓
node intake-issues.mjs         ← dry-run 预览（去重、补字段、标注缺失）
node intake-issues.mjs --write ← 写成 课程问题池/问题条目/YYYY-MM-DD-NNNN-*.md
   ↓
面板里就能看到（面板直接读这个目录）
   ↓
AI 起草答复 → 你人工过一遍 → 回帖到 issue
   ↓
判定「已沉淀」→ 导出进 public/FAQ/ → 下次发布带出去
```

### fetch-issues.mjs 用法

```bash
node fetch-issues.mjs                      # 拉公开仓（匿名），写进 inbox/
node fetch-issues.mjs --state open         # 只拉未关闭的
node fetch-issues.mjs --since 2026-09-01   # 只拉这之后有更新的
node fetch-issues.mjs --dry-run            # 只报告新增，不写文件
node fetch-issues.mjs --token <PAT>        # 私有仓 / 提高限额
node fetch-issues.mjs --out issues.json    # 纯 JSON 落盘（Windows 推荐）
```

**两个必须知道的限制：**

1. **匿名限流 60 次/小时/IP。** 够了 —— 每次运行只发 1 个请求。用尽时脚本会直接告诉你
   几点重置，或加 `--token <PAT>` 提到 5000 次/小时。
2. **Windows 下不要用 `node fetch-issues.mjs --json > f.json`。** PowerShell 的 `>`
   会把输出写成 UTF-16 并混入 stderr，拿到的不是合法 JSON。用 `--out`，或
   `--json | Out-File -Encoding utf8 f.json`。

**面板读的是 `课程问题池/问题条目/` 目录**，所以只要 issue 被规范化成条目文件，你的面板就自动有了。这一步目前还是人工/待自动化。

## 五、需要你先做的一步：安装 git

当前机器**没有 git**（`git --version` 报 CommandNotFound），也没有 `winget`。没有 git 就没法建仓库、没法 push。

三种任选：

1. **官网安装包**（最稳）：https://git-scm.com/download/win ，装完重启终端
2. **如果 winget 可用**：`winget install --id Git.Git -e`
3. **GitHub Desktop**：https://desktop.github.com/ —— 自带 git 且图形界面，适合不想碰命令行的场景

装完后告诉我，我接着做：

- 初始化 `public/` 为独立仓库（含 `.gitignore`）
- 生成首次 commit（建议信息：`publish: 模块二 课时7-12 教案（首个可发布版本）`）
- 把 `课程发布/` 和私有工作区的关系写清楚（建议：私有工作区也建仓，但**只本地或私有远端**）

## 六、还有一个必须你定的决定

### 公开仓放哪、谁能看

| 选项 | 成本 | 风险 |
| --- | --- | --- |
| GitHub **公开**仓 | 0 | 全网可见。教案内容会被搜索引擎收录，**不建议** |
| GitHub **私有**仓 + 加学生为 collaborator | 0 | GitHub 私有仓 collaborator **有读权限也有写权限**，且能看 Issues。学生数一多就难管 |
| GitHub **私有**仓 + 只把 issue 入口给出去 | 0 | 但私有仓的 issue 外部人提不了 —— 会退化成收不到问题 |
| 自建（Gitea / 校内 GitLab） | 服务器成本 | 可控但需运维 |

**这里有个真实矛盾**：GitHub 的权限模型里，"能提 issue"和"能看到仓库内容"是绑在一起的。

所以更现实的做法可能是**拆成两个公开/半公开面**：

- **资料面**：一个只放已发布资料的仓库（学生只读）
- **提问面**：一个**空的** issues-only 仓库，或直接用表单 → 再由 Agent 导入

要不要这样做，取决于你打算用 GitHub 还是别的平台。**这个决定需要你来做**，因为它涉及你把资料放在哪、接受什么可见性。

## 七、当前明确的边界（别越线）

| 做法 | 结论 |
| --- | --- |
| 学生配对进你的 DSH GUI | ❌ **绝对不行**。配对 = 你电脑的完整控制权 + 你的 API Key |
| 学生用你的 API Key 提问 | ❌ 会烧你的额度且无法计量。学生必须用自己的 Key |
| 把草稿和已发布内容放同一仓库 | ❌ 学生只读也能看到草稿。必须用复制式发布 |
| 助教配对进 GUI | ⚠️ 可以但需知情，用完立刻撤销。等同给他你电脑的控制权 |
| FAQ 直接导出公示 | ⚠️ 必须逐条人工过。里面可能有学生原话 |
| 发布前跑 `check` | ✅ 每次都跑 |

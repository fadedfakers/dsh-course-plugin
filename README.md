# 课程插件（鼹鼠仔 · 至圣先师鼹鼠精）

两个可独立安装的 **DSH 插件**，加一个共享内核。用来把一门课变成一个能用的教学系统：

| 包 | 显示名 | 作用 |
| --- | --- | --- |
| `dsh-course-student` | 鼹鼠仔 | 学生端：提问与多轮追问（自费额度）、作业提交与**按教案批改**、公开问答 |
| `dsh-course-teacher` | 至圣先师鼹鼠精 | 教师端：审计与答复、共性问题、学生名册、教案补全、大纲体检、**归档发布** |
| `dsh-course-core` | （内核） | 两端共用：工作区解析、课程树、缓存、教案、身份、zip、材料归位、仓库管理 |

三个包放在同一个仓库里，因为它们必须一起装、且版本要一致（两个端各 `require` 内核的宿主半区与客户端半区）。

---

## 一、这个插件不是为某一门课写的

这是最重要的一条设计约定：

> **凡是「换一门课就该不一样」的东西，都在配置里，不在代码里。**

具体地，`课程配置.json` 里的 `layout` 决定插件怎么认你的文件：

```jsonc
{
  "title": "深度学习课程",
  "code": "DL2026",

  "layout": {
    "chapters": ["第一章", "第二章", "第三章"],   // 章节名（空数组 = 这门课不分章）
    "modules": ["模块一", "模块二", "模块三", "模块四", "模块五"],
    "indexRel": "课程中心/课程结构索引.json",      // 结构索引在哪
    "slidesDir": "课程中心/预览数据",              // 课件在哪
    "planDir": "详细教案",                         // 教案在哪
    "questionsRel": "课程问题池",                  // 提问与答复放哪
    "submitRel": "作业提交"                        // 作业放哪
  },

  // 受控词表。⚠️ 它们进提示词与下拉框：换课必须一起换，
  // 否则模型会拿「视觉任务」去分类一门文学课的问题（分类错了不报错，只是归类莫名其妙）
  "topics": ["数学推导", "损失与优化", "工程与调试", "其他"],
  "issueTypes": ["概念问题", "代码报错", "环境问题", "作业疑问"],
  "severities": ["阻塞", "高", "中", "低"],

  // 教案骨架（不同课的「验收标准」写法完全不同）
  "planSections": ["目标", "推导", "实操", "验收标准", "当堂交付物"]
}
```

**读不到就用内置默认值** —— 所以默认形状是「章节 + 模块 + 教案 + 课件」这一套。
如果你的课不是这个形状（比如只有讲次和讲稿），改 `layout` 就行，代码一行不用动：

```jsonc
{ "layout": { "chapters": ["绪论", "线性表"], "planDir": "讲稿", "questionsRel": "答疑" } }
```

## 二、安装

需要 DSH（DeepSeek Harness）。三个包都要装。

```sh
# 把仓库 clone 到本机后，在仓库根目录执行：
dsh plugin --profile web add ./dsh-course-core
dsh plugin --profile web add ./dsh-course-student
dsh plugin --profile web add ./dsh-course-teacher
```

`dsh plugin` 会把参数转发给 profile 目录里的包管理器，并同时更新
profile 的 `dependencies` 与 `dsh.profile.bundles` 两处 ——
**两处必须都对，否则会出现「装了但没挂载、且没有任何提示」**。

装完**重启 DSH**：宿主半区是进程启动时加载的。只改客户端资源才只需刷新页面。

### 装完之后你看到什么

面板不会让你先填一张长表。它会先给一张**就绪清单**，把「说不清的故障」变成「缺哪一项」：

| 缺什么 | 你会看到的症状（如果不告诉你是哪一项） |
| --- | --- |
| 课程工作区 | 面板全空，像是插件坏了 |
| 课程结构索引 | 不知道这门课有哪些课时 |
| 模型 | 一提问就报错，而报错看起来像网络问题 |
| 学生身份 | 功能全正常，只是老师看到的提问者是机器用户名 |

### 工作区怎么找

按顺序试，第一个验证通过的胜出：

1. 环境变量 `CIP_COURSE_DIR`（直接指定一门课的目录）
2. 环境变量 `CIP_WORKSPACE`（+ 可选 `CIP_COURSE_CODE`）
3. 配置文件 `~/.dsh/cip-workspace.txt`
4. 内置默认值

「验证通过」的判据是这个目录里确实有 `课程中心/课程结构索引.json`。
多门课用共享式布局：根目录放共享内容（课件、索引、教案），
每门课的私有数据放 `课程/<课程码>/`。

## 三、两端的路由与面板

两个插件装在同一个 DSH 进程里同时运行 —— 这是老师要在一台机器上对测两端的前提。
硬约束只有一条，来自 DSH 本身：`webServer.register` 对重复的 `(kind, path)` **直接抛错**。

| 包 | 路由前缀 | 侧栏面板 id | 调用模型 |
| --- | --- | --- | --- |
| `dsh-course-student` | `/cip-stu` | `course-student` | **是**（费用归学生） |
| `dsh-course-teacher` | `/cip-tea` | `course-teacher` | 否 |

前缀不重叠，所以两个插件能共存。

## 四、数据怎么在两个端之间流动

两个插件通过**同一个课程工作区目录**交换数据，目录分工保证每个位置只有一个写入方：

| 目录 | 谁写 | 谁读 |
| --- | --- | --- |
| `课程问题池/公共/` | 教师端（审计为「值得共享」时写副本） | 学生端、教师端 |
| `课程问题池/学生/<学号>/` | 该学生自己 | 教师端（全量）、本人 |
| `作业提交/<学号>/` | 该学生自己 | 教师端（全量）、本人 |
| `课程中心/` | 公开仓分发 | 两端 |

「值得共享」是**写副本，不是移动**：原条仍留在该学生的私有目录里，
他的历史不会因为老师的一次操作而消失。

同步靠 git：老师 `publish` + push，学生 pull。插件里能看到待发布清单、
能替你跑发布工具，但**不替你做 commit/push** —— 那一步要用你的凭据，插件里不放任何人的密钥。

## 五、开发

三个包都**没有构建步骤**：`main` 直接指向 `src/host.js`，客户端半区是已构建好的 `lib/client.js`。
改宿主代码重启 DSH 生效；改客户端代码刷新页面生效。

`dsh-course-core/lib/client-shared.js` 是**构建产物**（markdown/公式渲染、课程树、图片组件），
由抽取脚本从已经验证过的客户端里抽段生成 —— 两个插件必须用**逐字一致**的渲染核心，
复制一份出来就会开始漂移。这个项目已经因为「两端对同一个字段的理解不一致」吃过一次大亏，
所以共享的部分一律只有一份。

KaTeX 直接内置在 `dsh-course-core/lib/katex/`，不需要联网下载。

## 六、已知边界

- **`/cip-stu-api`、`/cip-tea-api` 无鉴权**。假定只绑在本机回环或受信隧道后面。
  两个插件的角色差异是**界面与工作流**的差异，不是网络安全边界 ——
  学生端装在学生机器上，那里的工作区只有他自己那份数据。
- 学生身份取 `CIP_STUDENT`，缺省回落到系统用户名（此时面板会提示「你还没填学号」）。
- 教案批改、标题凝练、共性问题归纳要调用模型；**教师端的审计、汇总、发布是纯读写，不花额度**。
